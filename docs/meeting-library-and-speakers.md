# 회의 목록과 화자 편집

이 문서는 새 Tauri 앱의 소스 계약을 설명한다. 설치 앱, 실제 회의의 정확도와
운영체제별 실기 검증 결과는 별도 확인 대상이다. 기존 Swift 앱의 폴더/화자 구현과
혼용하지 않는다.

## 회의 목록

| 기능 | 현재 동작 |
| --- | --- |
| 생성/수정 | 회의 생성, 제목/메모/회의 날짜 수정. 기본 이름에는 사용 가능한 번호를 붙이며 사용자가 지정한 같은 제목은 허용함 |
| 보기 | 폴더별/전체 회의, 미분류, 사용자 폴더, 휴지통. 접힌 아이콘 rail/hover 확장/고정 지원 |
| 최근 회의 | 접기 가능. 제목/길이와 폴더/시각의 2행, 본 목록과 공통 우클릭/더보기 작업 |
| 일정 기반 생성 | 새 회의 옆 메뉴에서 오늘/과거/미래의 특정 날짜를 선택해 회의 준비 |
| 폴더 | 생성/이름 변경/삭제. 중첩 없이 회의당 폴더 하나. 폴더 삭제 시 내용은 미분류로 이동함 |
| 이동 | 개별/일괄 선택과 폴더 드래그 이동. 음성 파일의 실제 경로와 회의 ID는 바꾸지 않음 |
| 삭제 | 휴지통 이동, 복원, 확인 후 영구 삭제 |
| 검색 | 제목, 메모, 음성 기록 본문, 화자 이름, 회의록. 별도 모델을 로딩하지 않음 |

목록은 별도 선택 모드 없이 체크박스/Space로 선택한다. 일반 클릭은 회의를 열고,
Cmd(macOS)/Ctrl(Windows)+클릭은 추가 선택, Shift는 현재 표시 순서의 범위를 선택한다.
선택이 있으면 제목 옆에 개수와 일괄 작업을 표시하고, 0개면 숨긴다. 목록/작업줄의
Cmd/Ctrl+A는 현재 결과만 선택하며 Esc는 열린 메뉴/대화창 다음에 선택을 해제한다.
검색/폴더 변경으로 보이지 않게 된 선택은 유지하지 않는다. 휴지통 전체 비우기는
선택 삭제와 구분해 아이콘+이름을 표시하며, 선택 중에는 숨긴다. 삭제 확인의 대상
검증, 복원 불가 안내와 취소 우선 초점을 유지한다.

회의 드래그는 실제 회의 ID와 선택 묶음을 사용한다. 드롭 전에 편집을 저장하고
최신 목록에서 출발 배치와 대상 폴더를 다시 확인한다. 외부 파일, 삭제된 폴더,
오래된 배치에서 시작된 이동은 실행하지 않는다. 폴더 이동은 녹음/작업을 취소하지
않는다. Windows HTML 드래그가 기본 native file-drop에 가로막히지 않도록 main
창의 해당 가로채기를 끄며, 음성 가져오기는 기존 파일 선택 창을 유지한다.

태그와 중첩 폴더는 구현 범위에 포함되지 않는다. 회의 폴더와 참석자 그룹은 서로 다른 개념이다.

검색은 입력 지연과 요청 순서 검사로 이전 검색 결과가 새 검색을 덮지 않게 한다.
회의별 읽기 요청을 나눠 녹음 상태 처리가 중간에 실행될 수 있게 한다. 일부 결과를
읽지 못하면 부분 검색 안내를 표시하며, 읽기 실패를 검색 결과 없음으로 단정하지 않는다.

## 회의 내용 탐색

- 공통 제목/날짜와 녹음/재생은 내용 탭 밖에 유지한다. `요약`, `음성 기록`,
  `메모`를 상단의 같은 위치에서 선택하며, 원문 길이와 무관하게 접근한다.
- 회의의 기본 화면은 요약이다. 결과가 아직 없는 녹음 중 회의는 메모를 연다.
  사용자가 고른 보기와 스크롤은 회의별로 기억한다. 음성 기록은 상단에서 바로 열 수 있다.
- 결과 읽기가 끝나기 전과 결과 없음은 구분한다. 초기 기본값은 최초 읽기가
  끝난 뒤 한 번 결정하고, 이후 사용자가 고른 탭을 작업 완료나 늦은 응답으로 바꾸지 않는다.
- 탭/회의별 읽던 위치를 실행 세션 동안 기억한다. 빈 패널에 먼저 위치를
  적용하지 않고 해당 내용의 읽기/렌더가 끝난 뒤 복원한다.
- 메모/음성 기록의 조합 입력과 미저장 수정을 저장한 뒤 탭을 바꾼다.
  저장에 실패하면 현재 패널과 입력을 유지한다. 패널 전환은 재생기를 재생성하지 않는다.
- 유효한 요약 근거는 음성 기록 탭을 열고 해당 발언으로 이동한다. 편집으로
  출처 버전이 달라진 요약에서는 근거 이동을 제공하지 않는다.
- `meeting-detail-ui.js`가 선택/표시/스크롤을 소유한다. 개별 결과 렌더러가
  패널을 숨기지 않는다. `.content-tabs`의 시각 규칙은 디자인 시스템이 소유한다.

## 저장과 삭제

- `library.json` 하나가 폴더, 회의의 폴더/휴지통 배치, 관리 인원/그룹과 회의별 참석 명단을 소유한다.
  회의 스냅샷의 `folderId`/`deletedAt`/`attendees`는 이 문서의 투영이며 별도 정본이 아니다.
- 라이브러리 변경은 복사본 검증 후 문서 전체를 원자적으로 교체한다. 교체 후
  동기화 실패가 발생해도 실제 저장된 정본에 맞춰 메모리 상태를 다시 반영한다.
- 회의 본문, 원음, 재생 음성, 원시 모델 결과, 수정 기록과 회의록은 회의별 저장소에
  유지한다. 폴더 이동은 이 파일들을 복사하거나 옮기지 않는다.
- 휴지통은 배치 정보만 바꾸며 원음과 결과를 유지한다. 복원은 기존 폴더를 유지하지만,
  그 폴더가 삭제됐다면 미분류로 복원된다. 휴지통에서는 결과를 읽을 수 있고
  새 녹음/변환/요약/본문 수정은 허용하지 않는다.
- 영구 삭제는 휴지통의 회의만 대상으로 한다. 삭제 tombstone을 정본에 먼저 기록해
  목록에서 제외한 뒤 파일을 정리한다. 정리가 중단되거나 실패해도 해당 회의가
  재실행 후 다시 나타나지 않는다. tombstone ID를 새 회의에 재사용하지 않는다.
- 파일 정리 실패는 부분 완료로 표시한다. 앱을 다시 열 때 원음 저장소와 소유 관계가
  확인된 임시 처리 파일의 정리를 재시도하며, 실패가 계속되면 비차단 오류를 표시한다.
  오류 없이 영구 삭제가 완료됐다고 단정하지 않는다.
- 새 처리 작업은 `processing/<job-id>/owner.json`으로 회의 소유권을 기록한다.
  과거 임시 작업은 원시 결과가 한 회의의 보존된 원문과 정확히 일치할 때만 연결한다.
  소유 관계가 없거나 여러 회의와 일치하는 과거 파일은 임의로 지우지 않는다.
  따라서 모든 과거 파생 파일이 제거됐다고 주장할 수 없다. 공유 모델은 삭제 대상이 아니다.

## 작업 중 변경

- 제목/메모/음성 기록의 미저장 수정과 한국어 조합 입력을 저장한 후 목록 변경을 시작한다.
  저장 실패 시 수정 내용을 보존하고 후속 변경을 진행하지 않는다.
- 녹음 중이거나 일시정지한 회의의 삭제는 화면과 Core에서 거부한다.
- 변환/요약 중인 회의를 삭제하면 해당 작업만 취소하고 실제 워커 종료를 기다린 후
  휴지통/영구 삭제를 적용한다. 다른 회의의 작업이나 모델 다운로드를 취소하지 않는다.
- 가져오기 완료 직전에 새 회의가 보이는 경우에도 작업 소유권이 연결될 때까지
  기다린다. 삭제와 새로운 녹음/추론 시작은 같은 처리 경계를 사용한다.
- 저장 단계도 삭제 상태와 회의 존재를 다시 검사한다. 뒤늦게 끝난 변환/요약이나
  오래된 편집 요청이 삭제한 회의를 복원하거나 현재 결과를 덮어쓸 수 없다.
- 휴지통 복원은 취소한 작업을 자동으로 다시 실행하지 않는다. 취소는 원음과
  이미 저장된 결과를 유지한다.

## 참석 명단

관리 인원과 인원 그룹은 회의별 참석 명단과 분리한다. 회의 명단에는 안정적인 참석자 ID,
선택적 관리 인원 ID와 선택 당시 이름을 저장한다. 관리 인원 이름 변경/삭제는 과거 회의의
이름을 바꾸지 않는다. 그룹은 관리 인원의 ID만 묶으며 폴더에 종속되지 않는다.
이름이 같은 별도 인물은 허용하고 한 명단에서 같은 관리 인원의 중복 선택은 거부한다.

녹음 전/중/후에 관리 인원/그룹을 선택하거나 회의 전용 이름/이름 없는 임시 참석자를
추가하고 명단을 수정할 수 있다. 이름 없는 참석자의 표시 번호는 명단의 임시 항목 순서이며
실제 발언자 번호가 아니다. 회의 전용 참석자의 관리 인원 승격은 카탈로그 생성과 명단 연결을
한 번의 원자 저장으로 처리하며 양쪽 수정본을 검사한다.

참석 명단은 실제 발언, 목소리 식별이나 화자 배정의 증거가 아니다. 명단 편집은 원음/전사를
바꾸거나 분석을 자동으로 시작하지 않는다. 명단 인원수로 Nemotron slot을 강제 병합하지 않는다.

## 회의 메모와 요약

새 요약은 현재 음성 기록, 회의 메모, 참석 명단과 기존 요약 ID를 함께 고정한다. 명단은 참고 정보이며 순서나 추측으로 발언자 이름을 붙이는 근거가 아니다. 명단 snapshot/hash도 보존하고 명단 변경은 늦은 요약 저장 거부와 오래된 요약 표시에 반영한다. 관리 인원 카탈로그만 이름 변경/삭제하면 회의 snapshot이 같으므로 요약 상태를 바꾸지 않는다. 메모는
참고 배경이며 회의에서 말하지 않은 결정/담당자/기한을 만드는 근거로 사용하지
않는다. 메모와 별도 hash를 보존하고, 처리 중 메모가 달라지면 새 결과를 적용하지
않는다. 메모 변경은 새 요약을 오래된 결과로 표시한다. 과거 메모 hash가 없는
요약은 기존의 음성 기록 기반 의미로 읽으며 자동 재생성하거나 재작성하지 않는다.

## 화자와 수정 기록

기본 음성 인식은 전체 녹음을 하나의 Nemotron 3.5 스트림으로 처리하고 EOF에서
종료한다. 선택 가능한 Whisper large-v3-turbo는 문맥이 겹치는 정확한 PCM 구간을
처리한다. 두 경로 모두 원음과 인식 원문을 먼저 저장한 뒤 용어 정리와 별도 Nemotron 3 화자 분석을
같은 작업의 후속 단계로 실행한다. 화자 실패/취소는 저장된 음성 기록을 지우지 않으며,
화자 단계만 다시 시도할 수 있다. 기존 회의는 자동 재처리하지 않는다.

화자 분석은 하나의 연속 모델 상태를 유지한다. native compaction 전에 확률 프레임을
보존해 전체 녹음에 같은 `p > 0.5` 활동 규칙을 적용한다. V2 기반 padding/최소 길이
설정과 앞뒤 구간의 혼합 후처리는 새 경로에 사용하지 않는다. 고정 모델의 8개 slot은
익명 그룹이며 실제 참석자 수나 8인 회의의 검증된 정확도를 뜻하지 않는다.

단어 시각이 있는 Nemotron·Whisper 원문은 단어 시작부터 최대 160ms의 slot 확률 합을 비교하는
고정 native 규칙으로 배정한다. 이 값은 검증된 인물 이름이나 보정된 신뢰도가 아니다.
문장 일부에 여러 화자가 걸친다는 이유로 문장 전체를 미지정 처리하지 않는다.
새 단어 발언 경계는 원 ASR, parent snapshot/hash와 word span을 보존하는 별도
source-validated generation으로 저장한다. 수정문은 추측해 나누지 않으며 수동 배정과
사용자 이름을 새 slot에 임의 연결하지 않는다. 구세대 결과와 복원 경로를 유지한다.
단어 시각이 없는 과거 결과는 기존 보수적 활동 배정 경로를 사용한다.

Whisper는 native token 글자 조각을 복원한 뒤 실제 시작·끝 시각을 사용한다. 역전된
단어 시각은 비례 보간하지 않는다. 해당 native 문장 전체를 원래 문장 시각과
`nativeSegmentContext` 범위로 보존하고 화자는 미지정으로 둔다. 길이 0인 native
단어도 임의로 늘리거나 화자를 배정하지 않는다. 두 엔진의 원문·단어 화자 projection은
서로 다른 provider와 generation으로 검증한다. 모델 변경 후 명시적으로 재처리해도
과거 원문·수정·화자 기록과 CLI/MCP 읽기 전용 조회를 유지한다.

고정 Whisper 실행기의 마지막 native 문장이 부분 10ms tick의 다음 경계에 끝나는
경우만 별도 v2 정책으로 검증한다. 160 sample 미만의 초과를 문맥 범위로만 다루며,
문맥의 끝은 정확한 PCM 끝, 원래 끝은 `nativeSegmentEndFrame`으로 함께 보존한다.
단어 시각으로 보간하거나 화자를 배정하지 않는다. 더 큰 초과나 다른 구간의 초과는
계속 거부하며 원 JSON과 hash를 유지한다.

저장된 MOSS 결과는 기존 화자 범위와 EOS/전체 입력 검증 계약으로 읽는다. MOSS는 새
인식의 fallback이 아니다. 등록된 목소리 매칭은 연결되지 않았다. 실제 인물 식별이나
독립된 장시간 한국어 회의의 정확도는 별도 검증 대상이다.

| 항목 | 현재 계약 |
| --- | --- |
| 자동 표시 | 인식 결과의 화자 ID와 발언별 배정을 보존. 확인할 수 없으면 미지정으로 표시함 |
| 이름 변경 | 해당 회의의 같은 화자 ID에 연결된 이름을 변경하고 사용자 지정 출처를 보존함 |
| 배정 수정 | 선택한 발언을 기존 화자/새 화자/미지정으로 변경함 |
| 합치기 | 사용자가 선택한 두 화자를 합치며 발언 배정을 함께 변경함 |
| 취소/되돌리기 | 대화상자 취소는 미저장 수정을 버림. 현재 실행 중 버전이 일치할 때 직전 화자 수정 한 건을 되돌림. 재변환 실행별 이전 기록 선택/복원은 별도 기능임 |
| 충돌 | 읽었던 음성 기록 ID/revision이 달라졌으면 저장을 거부하고 현재 입력을 보존함 |

화자와 본문 수정은 같은 음성 기록 revision을 사용한다. 원음, 원시 결과와 초기
음성 기록은 수정하지 않고 수정본을 별도 보존한다. 화자 이름/배정 변경도 회의록의
입력 변경이므로 이전 회의록은 오래된 결과로 표시한다. 다시 요약할 때 현재 화자
표시와 발언 번호를 전달한다. 자동 화자 표식을 참석자 명단이나 인원으로 열거하지
않는다. 사용자 지정 이름은 해당 발언의 담당자 참조에 사용할 수 있으며 실제 목소리의
자동 신원 검증과 구분한다. 출처가 없는 과거 이름은 임의로 사용자 확정으로 승격하지
않는다. 복사와 TXT/Markdown 내보내기도 현재 배정을 사용한다.

전체 녹음 분석은 현재 문서 버전과 내용을 고정하고, 적용 시 다시 비교한다. 원음,
원본 음성 기록, 문장, 시각과 발언 ID는 유지하며 새 화자 배정을 별도 수정본으로
보존한다. 분석 원본, 모델/실행기 정보, 시간 투영의 판단 근거를 현재 문서 교체 전에
저장한다. 한 발언 구간에 여러 화자가 걸치거나 단일 화자의 활동이 구간 절반 이하이면
미지정으로 남긴다. 이 기준은 신원 신뢰도 점수가 아니다. 모델의 최대 여덟 출력 슬롯은
실제 여덟 명 회의의 품질 검증을 뜻하지 않는다.

현재 macOS/Windows 어댑터와 실행기 준비 코드는 플랫폼 실기 검증, 기본 자동 처리
정책이나 설치된 배포본의 변경을 뜻하지 않는다.

### 편집과 탐색

발언의 화자 버튼은 해당 문장/시각과 다시 듣기를 먼저 표시하고 그 발언만 변경한다.
전체 화자 관리에서는 이름/병합과 발언별 배정을 분리한다. 하나의 본문 스크롤과
고정된 저장/취소 영역을 사용하며 적용 뒤 원래 발언 또는 해당 작업으로 초점을 돌린다.
재청취는 선택한 발언의 끝에서 멈춘다. 이는 재생 경로이며 새 녹음을 시작하지 않는다.

발언 편집 중 탭 이동/회의 이동/다른 작업을 실행하면 저장을 먼저 마친다. 성공하면
편집기를 닫고 이동한다. 실패하면 현재 편집/입력을 유지한다. 이동 후 다시 돌아왔을 때
이미 저장된 문장을 되돌리는 것처럼 보이는 취소 버튼을 남기지 않는다.

회의 검색은 첫 일치의 문맥과 종류를 반환한다. 음성 기록/화자 일치는 문서 버전,
발언 ID와 위치를 함께 반환하고 상세 화면에서 다시 검증한다. 상세 내용 검색은
정규식이 아닌 문자 그대로의 검색이며 첫 일치를 드러낸 뒤 이전/다음으로 이동한다.
발언별 일치의 위치는 앞선 편집기 종료로 표시 개수가 달라져도 같은 발언을 유지한다.
메모 검색은 강조된 읽기 화면에서 해당 위치로 이동하고 검색창 초점을 유지한다. 검색을 닫으면 원문과 읽던 위치를 유지한 편집기로 돌아간다. 읽기 응답은 시작한 문서/버전이 그대로일
때만 반영하여 저장/복원 이후의 오래된 응답이 현재 문서를 덮지 않게 한다.

### 이전 음성 기록

기존 기록의 다시 변환은 문장/화자 수정 교체를 알리는 확인을 거친다. 이전 기록은
회의의 transcript UUID 폴더별 최신 수정 문서를 조회하며 매 편집 revision의 스냅샷을
뜻하지 않는다. 일반 조회는 이관이나 원문 복구를 수행하지 않는다.

목록에는 현재/이전 여부, 저장 시각, 발언 수와 수정 여부를 표시한다. 저장 시각은
파일 수정 시각이며 녹음 시각이나 변환 시작 시각으로 추정하지 않는다. raw/initial/
current의 원본 연결을 확인한 문서만 복원할 수 있고 불완전하거나 손상된 결과는
조회 불가 개수로 남긴다. 기존 파일을 삭제하거나 불확실한 연결을 재구성하지 않는다.

복원은 현재 문서와 대상 문서의 ID/revision을 모두 비교한 뒤 대상 revision을 증가시키고
현재 포인터를 변경한다. 녹음, 종료 준비와 해당 회의의 실행 중인 처리와 경합하면
거부한다. 원음/raw/initial과 기존 결과를 보존하고 기존 회의록은 오래된 결과로 남긴다.

### 원본 연결과 기존 문서 이관

발언의 동일성은 재생 시각의 float 값으로 판단하지 않는다. 새 음성 기록은 원시
결과의 SHA256, 변환 규칙 버전과 원본 구간 번호(`sourceIndex`)를 보존한다. 본문이나
화자 수정은 최초 문서의 발언 ID와 이 연결 정보를 유지한다.

기존 형식은 일반 읽기와 분리된 시작 단계의 이관 작업으로 처리한다. 불변
`initial.json`을 기준으로 transcript/세션/모델 정보, 발언 ID/순서/원문을 정확히
대조한다. raw/initial/current의 시간은 ASR 분석 음성의 16,000Hz 정수 샘플 주소로
검증한다. 시간 허용 오차나 인접 float 값으로 발언을 추측하지 않는다.

검증한 이관 입력의 raw/initial/기존 current 해시와 규칙 버전을 영수증에 남기고,
이전 current의 정확한 바이트와 새 문서를 별도 보관한 뒤 current를 원자적으로
교체한다. revision은 증가한다. 준비 영수증만으로 적용 완료를 주장하지 않고,
실제 current의 해시로 확인한다. 과거 raw 해시는 당시 실행에 저장된 증거가 아니라
이번 이관 입력을 고정한 값이므로 새 직접 생성 결과와 association을 구분한다.

이미 명시된 화자 이름/배정과 미지정은 유지한다. source가 저장된 문서는 다시
이관하지 않는다. initial/raw가 없거나 대응이 불확실하면 기존 본문은 유지하고
비차단 오류를 표시한다. 원시 결과와 initial은 변경하지 않는다.

향후 JSON 저장 왕복에서도 시간 값이 달라지지 않도록 워크스페이스의 공통
serde_json 설정에 `float_roundtrip`을 적용한다. 이 설정은 과거 문서의 연결 근거를
대신하지 않는다. [공식 정밀도 설정 설명](https://github.com/serde-rs/json/blob/master/Cargo.toml)

## 모델 구간의 한계

워커는 긴 음성을 나눠 각 구간을 독립적으로 인식한다. 서로 다른 구간의 `S1`은
같은 사람이라는 뜻이 아니다. `asr_chunk`가 있는 결과는
`moss:chunk:<구간 번호>:<모델 라벨>`로 구분하며, 구간 정보가 일부 빠지거나
잘못된 배정은 회의 전체의 동일인으로 추정하지 않는다. 화자 정보를 사용할 수 없어도
유효한 음성 기록 본문은 유지한다.

구간별 화자 항목 수는 실제 참석자 수가 아니다. 같은 사람이 여러 항목으로 나타날 수
있으며, 구간을 가로지르는 동일인 연결은 사용자가 확인해 합치는 단계다. 현재 기능을
회의 전체의 화자 분리/등록 화자 자동 인식이 완료된 상태로 설명하지 않는다.

최대 8명의 실제 화자는 품질 검증 목표이며 검증 완료된 지원 수가 아니다. 참석자가
늘어났다는 이유로 녹음이나 텍스트 변환을 막지 않는다. 실제 회의의 화자 구분,
겹치는 발화와 구간 경계 정확도는 목표 환경에서 별도로 평가해야 한다.

| --- | --- |
| 소스/합성 테스트 | 저장/복원, 충돌, 삭제 중 취소와 재생성 방지, 수정 보존, 구간별 라벨 분리 계약 확인 |
| 브라우저 UI | 가상 상태에서 목록/메뉴/대화상자/키보드/좁은 화면을 확인. 실제 파일/마이크/워커 동작의 증거가 아님 |
| 네이티브 앱 | 실제 앱에서 실행한 기능과 결과만 별도 기록. 빌드 성공은 장시간 녹음이나 모델 품질 검증을 대신하지 않음 |
