# 앱 안의 AI 대화

이 문서는 현재 소스의 동작을 설명한다. 배포된 버전의 기능은 릴리스 안내를 확인한다.

앱 우측의 AI 사이드바에서 Claude 또는 ChatGPT 구독 계정에 로그인해 질문한다. 대화는 회의와 독립적으로 유지한다. 화면을 이동해도 같은 대화를 계속 사용하며, 회의 메모와 AI를 동시에 열 수 있다. 별도 API 키를 받거나 API 과금 경로로 전환하지 않는다.

## 대화와 첨부

새 대화, 대화 목록과 삭제를 제공한다. AI 창은 화면의 회의를 따라간다. 회의를 열면 그 회의를 첨부해 질문한 가장 최근 대화를 보여 주고, 없으면 그 회의를 첨부한 새 대화를 띄운다. 새 회의는 항상 새 대화로 시작한다. 보내지 않은 초안은 그 회의로 돌아오면 다시 나타난다. 회의 목록 같은 회의가 없는 화면은 현재 대화를 바꾸지 않는다. 하나의 대화에서 여러 회의를 사용했다면 각 회의에서 그 대화가 열린다. 회의 화면의 대화 목록은 기본적으로 해당 회의의 대화를 보여주며 전체 대화로 전환할 수 있다. 사용자가 첨부를 제거하거나 다른 회의를 추가할 수 있고, 기존 대화를 열 때 현재 회의를 자동으로 추가하지 않는다. Notion은 사용자가 지정한 페이지만 읽는다. 회의를 첨부하면 그 회의에 저장된 Notion 자료도 대화의 제거 가능한 자료로 표시한다. 같은 페이지가 여러 회의에 있으면 첨부 순서상 첫 회의의 저장된 버전을 선택하며, 직접 추가한 버전이 있으면 이를 우선한다. 회의를 대화에서 제거하면 남은 회의의 버전으로 선택이 바뀔 수 있다. 질문을 보낼 때 선택 출처를 함께 저장해 대화를 다시 열어도 유지한다. 이전 기록에 선택 출처가 없으면 당시 선택한 자료를 그대로 유지한다. 회의 자료의 갱신이나 제거는 이미 대화에 선택된 자료를 자동으로 바꾸지 않는다.

질문을 보낼 때 회의 원문/메모/참석자와 선택한 Notion 문서를 변경 불가능한 입력 스냅샷으로 묶는다. 여러 회의의 발언과 외부 문서를 구분하고 인용 번호는 해당 요청 안에서 고유하게 부여한다. 문서 안의 지시는 실행하지 않는다. 과거 메시지의 첨부와 출처는 이후 화면 이동이나 원문 수정으로 바뀌지 않는다.

회의를 휴지통으로 옮기거나 삭제해도 대화와 진행 중인 답변은 유지한다. 삭제된 회의를 새 질문에 첨부하면 요청을 거절하며, 과거 스냅샷을 자동으로 다시 전송하지 않는다. 대화를 삭제하면 해당 대화의 답변만 중지하고 대화는 AI 대화 휴지통으로 옮긴다. 휴지통의 대화는 복원하거나 완전히 삭제할 수 있고, 이어서 질문하려면 먼저 복원한다. 기간이 지나도 자동으로 지우지 않는다.

AI 대화는 사이드바 레일의 폴더와 휴지통 사이에 있다. 레일에서 고르면 사이드바에 대화 목록이 나오고, 대화마다 첨부한 회의와 마지막 시각을 보여 준다. 대화를 누르면 오른쪽 AI 창에서 열리고 가운데 화면은 그대로 둔다. 대화 아래의 회의 이름을 누르면 그 대화를 연 채 회의로 이동하며, 보낸 질문의 회의 칩도 같은 동작을 한다. 사이드바 머리줄에서 새 대화를 시작하거나 가운데 관리 화면을 연다. 관리 화면은 대화마다 질문에 첨부한 회의를 보여 주며 대화를 눌러도 회의 화면으로 이동하지 않는다. 여러 대화를 골라 휴지통으로 옮기거나, 마지막 대화가 10일, 30일, 90일보다 오래된 대화를 한 번에 옮기거나, 전체를 옮길 수 있다. 답변 중인 대화는 한꺼번에 정리할 때 제외한다.

보낸 질문은 수정해 다시 물을 수 있다. 수정한 질문은 원래 질문과 같은 자리에서 새 버전이 되고, 그 아래 이어진 대화는 이전 버전에 남는다. 새 답변은 수정한 지점 이전의 대화만 맥락으로 받는다. 버전은 질문 옆에서 바꿔 볼 수 있고 마지막으로 고른 버전을 기억한다. 입력창이 비어 있을 때 위 화살표를 누르면 현재 대화에서 보낸 질문을 최근 것부터 불러오고, 아래 화살표로 되돌아가면 쓰던 초안이 돌아온다.

## 회의 요약과 템플릿

`/회의요약`은 회의 하나와 템플릿 하나가 필요하다. 템플릿은 요약 스킬을 고른 뒤에만 보이며 따로 고르는 입구는 없다. 스킬을 고르면 회의 요약 화면에서 고른 템플릿을, 없으면 기본 템플릿을 미리 고르고 스킬 칩 안에서 바꾼다. 질문을 쓰지 않고 보내면 저장되는 질문은 비어 있고, 모델에는 스킬이 정한 요약 요청이 전달된다. 보낸 질문에는 입력 영역과 같은 회의, 스킬, 템플릿 칩과 직접 쓴 글만 보인다. 전송 시 선택 ID로 저장된 최신 템플릿을 읽어 이름, revision과 프롬프트를 요청 스냅샷에 보존한다. 이후 템플릿을 수정하거나 삭제해도 이미 보낸 요청은 바뀌지 않는다. 재시도는 선택한 템플릿 ID를 유지하고 전송 시점의 저장된 내용을 다시 읽는다.

완료된 `/회의요약` 답변은 지정한 회의의 요약으로 저장을 시도한다. 저장은 기존 회의 맥락과 버전을 검사하며, 저장 성공 응답을 확인해야 완료로 표시한다. 실패한 경우 오류를 표시하고 기존 내용을 보존한다.

음성 기록이 있고 요약이 없거나 이전 내용으로 만든 요약이면 회의 본문의 **네로로 요약** 또는 **최신 내용으로 정리**에서 현재 회의와 요약 스킬을 준비할 수 있다. 기존에 쓰던 질문은 보존하며 자동 발송하지 않는다. 템플릿을 확인한 뒤 사용자가 보낸다. 비활성 로컬 요약 모델의 준비/다운로드 항목은 초기 설정과 설정에서 숨긴다. 저장된 요약과 공용 요약 템플릿은 유지한다.

## 답변 표시

완료 답변의 실제 모델 ID는 **응답 정보**에서 확인한다. 답변 본문에 같은 정보를 매번 별도 줄로 표시하지 않는다.

답변과 요약은 CommonMark와 GFM(표, 체크 목록, 취소선, 인용, 링크)으로 해석해 허용한 태그로만 그린다. 모델이 쓴 HTML은 실행하지 않고 글자로 보여 준다. 링크는 계정 정보가 없는 https 주소만 외부 브라우저로 열며 앱 창 안에서는 이동하지 않는다. 생성 중인 답변은 덜 끝난 서식을 닫아 표시하고, 끝에 걸린 미완성 인용 번호는 완성될 때까지 표시하지 않는다. 인용 바로 뒤의 문장 부호는 인용 앞으로 옮겨 문장에 붙여 그린다.

## 저장과 복사

완성된 답변은 첨부된 회의 중 사용자가 선택한 회의의 요약으로 저장하거나 메모에 추가할 수 있다. 생성할 때 캡처한 원문, 메모, 참석 명단이 그대로인지 다시 확인하며, 편집된 내용을 덮어쓰지 않는다. 제목, 폴더, 회의 날짜, 캘린더 연결의 변경이나 그사이 저장된 다른 요약은 답변을 낡게 만들지 않고, 요약으로 저장한 답변이 현재 요약을 대신한다. 음성 기록이 없는 회의의 메모 추가는 회의 전체 버전을 확인한다. 메모 편집기에서 그 회의의 메모를 쓰는 중이었다면, 편집 저장은 그사이 끝에 추가된 답변을 사용자의 글 뒤에 남긴다. 그 밖에 다른 곳에서 바뀐 제목이나 메모는 저장하지 않고 알리며, 그 상태에서 다시 저장하면 덮어쓴다. 같은 답변을 같은 대상에 중복 저장하지 않는다. 요약은 그 답변이 아직 현재 요약일 때만 이미 저장된 것으로 보고, 그사이 다른 요약으로 바뀌었으면 다시 저장한다. 완성되지 않은 답변에는 저장 동작을 제공하지 않는다.

여러 회의를 다룬 답변을 한 회의에 저장할 때 그 회의의 인용 번호만 원문 번호로 대응한다. 다른 회의의 발언은 회의명과 시각으로 구분하고 Notion 인용은 외부 링크로 유지한다. 회의명이나 Notion 제목이 `[2024-05-01]`처럼 괄호 숫자여도 원문 발언 번호로 읽지 않는다. 회의명의 괄호는 이스케이프하고, 요약 저장의 근거 번호 검사는 링크 글자를 건너뛴다. 숫자 인용 범위 검사는 문장의 의미가 출처와 일치한다는 보증이 아니다. 형식이 맞고 모든 번호가 그 답변에 첨부된 자료인 괄호만 인용으로 보며, 체크 목록 `[ ]`, 연도 `[2024]`, 범위를 넘는 `[40-80]`, 모델이 지어낸 번호는 글자로 남긴다. 이런 괄호 때문에 답변을 실패로 저장하지 않고, 요약이나 메모로 저장할 때는 이스케이프해 원문 발언 번호로 읽히지 않게 한다.

완성된 답변은 텍스트 또는 마크다운으로 복사한다. Core의 공통 문서 변환을 사용해 내부 인용 번호를 제외하고 외부 문서 링크를 유지한다. 복사는 특정 회의의 존재나 선택을 요구하지 않는다. 회의 기록과 AI 답변의 복사는 본창 전용 네이티브 클립보드 쓰기를 공유하며 브라우저의 일시적인 클립보드 권한에 의존하지 않는다. 복사할 내용은 16 MiB로 제한하고 쓰기 실패는 사용자에게 알린다.

## 저장 구조와 연결

- `ai_chat/store`: 앱 데이터의 `ai-conversations/<UUID>.json`에 대화를 원자 저장한다. 회의 폴더를 만들거나 다시 생성하지 않는다. 이전 회의별 대화는 네이티브 작성자의 첫 전역 대화 사용에서 멱등 수입하며 원본을 보존한다. 수입 기록은 삭제한 대화가 다시 나타나지 않도록 한다. 메시지는 앞 메시지(`parentId`)를 기억하고, 대화는 갈라진 지점마다 보여 줄 질문 버전(`versions`)과 휴지통으로 옮긴 시각(`deletedAt`)을 함께 저장한다. 이 정보가 없는 이전 파일은 순서대로 이어진 하나의 대화로 읽는다. 일반 CLI/MCP 조회는 수입이나 마이그레이션을 실행하지 않는다.
- `ai_chat/context`: 첨부된 회의별 버전/요약 맥락과 고유한 인용 번호, Notion 출처 ID/내용 해시, 입력 스냅샷을 묶는다. 같은 대화에서 입력 해시(`inputSha256`)가 같은 스냅샷은 처음 한 번만 저장하고 이후 답변은 해시로 그 스냅샷을 가리킨다. 대화 목록은 크기와 수정 시각이 바뀐 대화 파일만 다시 읽는다.
- `ai_chat/provider`: ChatGPT의 HTTPS 응답 스트림을 처리한다. `claude_runner`: 서명을 확인한 공식 Claude Code 실행기의 구조화 스트림을 처리한다. 완료 여부를 확인하고 오류와 취소 시 부분 결과를 보존한다.
- `ai_accounts`/`notion_context`: ChatGPT와 Notion의 Nero 전용 로그인, 자격 증명 저장과 갱신을 담당한다. Claude 인증은 Claude Code가 소유하며 Nero는 기존 Claude 자격 증명을 읽거나 복사하지 않는다.
- `meeting_context`: 회의별 Notion 자료의 불변 출처 ID를 저장한다. 문서 본문은 공통 Notion 캐시에만 저장한다.
- `ai_chat_desktop`: 메인 창의 명령과 이벤트, 브라우저 열기, 종료/업데이트 경계를 연결한다.

ChatGPT와 Notion의 브라우저 로그인 화면은 콜백 수신과 실제 연결 완료를 구분한다. 토큰 검증과 안전한 저장이 끝난 뒤 완료 화면을 표시하고 자동 닫기를 시도한다. 브라우저가 닫기를 허용하지 않으면 사용자가 닫을 수 있다.

설정의 `AI 계정`은 Nero 내부 대화에 사용할 로그인이다. `MCP 연결`은 다른 AI 앱에 Nero 도구를 등록하는 연결이며, `Notion 연결`과 `Google Calendar`는 별도로 관리한다. Notion의 내부 통신이 MCP여도 외부 AI 앱의 Nero 도구 등록과 구분한다.

일반 계정 상태 조회는 공개 메타데이터만 읽는다. 네로 패널 또는 설정 > 연동을 열거나 해당 화면이 열린 채 앱으로 돌아오면 기존 로그인을 자동 확인한다. 같은 확인이 진행 중이면 공유하고, 자동 확인은 1분 이내 반복하지 않는다. ChatGPT는 저장된 계정을 비대화형으로 복원하며, Claude는 서명과 준비 기록을 검증한 기존 공식 실행기의 인증 상태만 조회한다. 자동 확인은 실행기를 설치하거나 브라우저 로그인, 모델 목록 갱신, AI 요청을 시작하지 않는다. 확인 오류는 기존 계정/모델 선택을 유지해 표시하며, 다시 확인은 사용자가 접근 재승인을 요청하는 명시적 동작이다. 앱 재시작 후 확인되지 않은 계정을 로그아웃으로 단정하지 않는다. 모델 메뉴는 모델 검색과 연결된 서비스만 보여 주고, 서비스를 고르면 같은 자리에서 그 서비스의 모델 목록으로 바뀐다. 검색어를 넣으면 모든 연결된 서비스의 모델을 한 목록으로 보여 준다. 확인 전 상태에서 계정 ID 없이 만들어지는 서비스 자리표시는 계정으로 보지 않으며, 그 자리로 모델 목록을 받거나 자격 증명을 읽지 않는다. 선택한 서비스에 사용할 계정이 없으면 계정이 있는 서비스로 바꾼다. 모델 메뉴를 열면 캐시된 목록과 선택을 즉시 표시하고, 앱 실행 중 계정마다 한 번 최신 목록을 받는다. 앱 시작, 설정 화면과 대화창 열기는 목록을 받지 않는다. 목록을 받지 못하면 기존 캐시와 선택을 보존하고 다시 시도를 제공한다.

ChatGPT는 Sign in with ChatGPT로 연결하고 계정의 모델 목록을 사용한다. macOS는 계정 자격 증명을 제한된 단일 키체인 항목에 저장하며 Windows 항목 크기 제한용 청크 저장과 구분한다. 기존 macOS 항목은 앱 프로세스의 비대화형 접근 범위 안에서 읽고 원래 UI 허용 상태를 복원한다. 복원에 실패하면 이후 저장소 접근을 중단한다. 기존 항목을 읽지 못하면 여러 항목의 암호를 연속 요청하지 않는다. 명시적으로 새 로그인을 완료해 검증/저장하기 전까지 기존 항목과 계정 목록을 보존한다. Claude는 사용자가 공식 Claude Code에 직접 로그인하며 기존 로그인 자동 확인, 실제 사용 결과와 명시적 로그인에서 상태를 확인한다. 앱은 수정하지 않은 공식 실행 파일의 서명을 확인하고, 필요 시 앱 전용 실행기를 준비한다. 기존 Claude Code 로그인 상태는 Nero에서도 사용할 수 있으며 Nero에서 연결을 해제하려고 외부 Claude Code를 로그아웃하지 않는다. Claude 모델 목록은 공식 실행기의 `supportedModels()`가 제공하는 이름을 표시하고 ID로 요청하며 별칭에서 버전을 추측하지 않는다. 실행기가 버전 없는 계열 이름(예: Sonnet)만 주면 같은 항목의 `resolvedModel`에서 읽은 버전을 붙인다. 실행기가 주는 목록과 이름은 같은 실행 파일에서도 달라질 수 있다. 다른 모델의 별칭인 `default` 항목은 표시하지 않고, 같은 계열에 더 새 버전이 목록에 있는 모델은 이전 모델 아래에 접어 둔다. 모델 목록은 로그인 완료 시 준비하고 저장된 목록을 다시 보여 준다. 모델별로 확인된 추론 수준은 모델 옆에서 선택하며 요청에는 항상 수준을 명시한다. 고르지 않았으면 ChatGPT는 모델 목록의 기본 수준을, Claude는 Claude Code 문서의 모델 기본값(추론 수준을 지원하는 모델은 high, Opus 5.5와 Sonnet 5.5와 Haiku 5.5는 medium, Opus 4.7은 xhigh, 2026-11-05 확인)을 쓴다. 기본 수준을 알 수 없는 모델은 수준을 고르기 전까지 보내지 않는다. 지원 정보가 없으면 확인 불가로 표시한다. ChatGPT 목록에 지원 정보가 없을 때는 OpenAI 모델 문서에서 확인한 정확한 모델 ID의 설정만 제공한다. 요청한 모델 ID와 실제 응답에서 제공된 `actualModelId`는 별도로 기록한다. 실제 계정의 사용 가능 여부는 실행 결과를 따른다.

Claude 요청은 별도 임시 작업 위치에서 도구와 MCP를 제한하고 세션을 저장하지 않는다. 사용자에게 터미널을 표시하지 않는다. 조직이 관리하는 정책은 계속 적용될 수 있다. 선택한 회의와 자료의 내용은 답변을 위해 해당 서비스에 전달된다. 답변이 실패하면 Claude Code 출력이 알려 준 오류 종류로 로그인 만료와 사용 한도를 구분해 알리고, 실행 파일을 열거나 실행하지 못하면 연결 확인을 안내한다. 취소와 그 밖의 실패는 각각의 메시지로 남는다.
