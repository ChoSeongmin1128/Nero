# 앱 안의 AI 대화

앱 우측의 AI 사이드바에서 Claude 또는 ChatGPT 구독 계정에 로그인해 질문한다. 대화는 회의와 독립적으로 유지한다. 화면을 이동해도 같은 대화를 계속 사용하며, 회의 메모와 AI를 동시에 열 수 있다. 별도 API 키를 받거나 API 과금 경로로 전환하지 않는다.

## 대화와 첨부

새 대화, 대화 목록과 삭제를 제공한다. 회의 화면에서 AI를 열면 현재 회의를 첨부하며, 사용자가 첨부를 제거하거나 다른 회의를 추가할 수 있다. 첨부하지 않은 회의는 화면 이동만으로 전송하지 않는다. Notion은 사용자가 붙인 페이지 링크만 읽는다.

질문을 보낼 때 회의 원문/메모/참석자와 선택한 Notion 문서를 변경 불가능한 입력 스냅샷으로 묶는다. 여러 회의의 발언과 외부 문서를 구분하고 인용 번호는 해당 요청 안에서 고유하게 부여한다. 문서 안의 지시는 실행하지 않는다. 과거 메시지의 첨부와 출처는 이후 화면 이동이나 원문 수정으로 바뀌지 않는다.

회의를 휴지통으로 옮기거나 삭제해도 대화와 진행 중인 답변은 유지한다. 삭제된 회의를 새 질문에 첨부하면 요청을 거절하며, 과거 스냅샷을 자동으로 다시 전송하지 않는다. 대화 자체를 삭제하면 해당 대화의 답변만 중지한다.

## 저장과 복사

완성된 답변은 첨부된 회의 중 사용자가 선택한 회의의 요약으로 저장하거나 메모에 추가할 수 있다. 생성할 때 캡처한 대상 회의의 버전과 원문 맥락을 다시 확인하며, 편집된 내용을 덮어쓰지 않는다. 같은 답변을 같은 대상에 중복 저장하지 않는다. 완성되지 않은 답변에는 저장 동작을 제공하지 않는다.

여러 회의를 다룬 답변을 한 회의에 저장할 때 그 회의의 인용 번호만 원문 번호로 대응한다. 다른 회의의 발언은 회의명과 시각으로 구분하고 Notion 인용은 외부 링크로 유지한다. 숫자 인용 범위 검사는 문장의 의미가 출처와 일치한다는 보증이 아니다.

완성된 답변은 텍스트 또는 마크다운으로 복사한다. Core의 공통 문서 변환을 사용해 내부 인용 번호를 제외하고 외부 문서 링크를 유지한다. 복사는 특정 회의의 존재나 선택을 요구하지 않는다.

## 저장 구조와 연결

- `ai_chat/store`: 앱 데이터의 `ai-conversations/<UUID>.json`에 대화를 원자 저장한다. 회의 폴더를 만들거나 다시 생성하지 않는다. 이전 회의별 대화는 네이티브 작성자의 첫 전역 대화 사용에서 멱등 수입하며 원본을 보존한다. 수입 기록은 삭제한 대화가 다시 나타나지 않도록 한다. 일반 CLI/MCP 조회는 수입이나 마이그레이션을 실행하지 않는다.
- `ai_chat/context`: 첨부된 회의별 버전/요약 맥락과 고유한 인용 번호, Notion 출처 ID/내용 해시, 입력 스냅샷을 묶는다.
- `ai_chat/provider`: 공급자의 HTTPS 응답 스트림에서 명시적 완료와 완결된 종료 사유를 확인한다. 출력 한도, 오류, 끊긴 연결과 취소는 부분 결과로 유지한다.
- `ai_accounts`/`notion_context`: Nero 전용 브라우저 로그인, 계정별 갱신, OS 보안 저장소와 종료 시 자격 증명 저장 완료 대기를 담당한다.
- `ai_chat_desktop`: 메인 창의 명령과 이벤트, 브라우저 열기, 종료/업데이트 경계를 연결한다.

브라우저 로그인 화면은 콜백 수신과 실제 연결 완료를 구분한다. 토큰 검증과 안전한 저장이 끝난 뒤 완료 화면을 표시하고 자동 닫기를 시도한다. 브라우저가 닫기를 허용하지 않으면 사용자가 닫을 수 있다.

ChatGPT는 SIWC 토큰의 모델 목록을 사용한다. Claude는 계정의 모델 목록 조회를 답변의 필수 선행 요청으로 두지 않는다. 선택지는 [Claude 공식 모델 목록](https://platform.claude.com/docs/en/models/overview)을 기준으로 관리하며, 해당 구독에서의 실제 사용 허용과 한도는 공급자의 답변 요청 결과를 따른다. 다른 인증 방식으로 재시도하지 않는다.

Claude의 응답 시작 전 `429` 중 `x-should-retry: true`이고 unified quota 헤더가 없는 경우만 최대 두 번 재시도한다. 서버가 지정한 대기 시간을 줄이지 않으며, 해석할 수 없거나 60초를 넘는 명시적 대기 값에는 자동 재시도를 하지 않는다. 대기/HTTP/응답 스트림은 하나의 600초 제한과 취소 신호를 공유한다. 일부 응답이 시작된 뒤에는 자동 재전송하지 않는다. 이 재시도 정책은 공급자의 요청 허용이나 서비스 성공을 보장하지 않는다.
